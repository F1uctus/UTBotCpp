# Что сделано в Windows-ветке UTBotCpp

## С чем сравнивается

Этот отчёт описывает отличия ветки `ci/portable-utbot-fixes` от ветки
`win-native` на коммите `53b96968f9b26b9853b5b4397718a8ed46589feb`.

Цель изменений — собирать UTBotCpp и KLEE нативно под Windows x86-64, проверять
реальную генерацию тестов и публиковать переносимый архив, который не зависит от
каталога сборки, WSL, MSYS или Cygwin.

## Изменения в исходном коде

### Сборка с официальным LLVM для Windows

- В `server/CMakeLists.txt` исправляется устаревший путь к `diaguids.lib`,
  записанный внутри официального архива LLVM. Используется DIA SDK из текущей
  установки Visual Studio.
- Это устраняет ошибку линковки `LLVMDebugInfoPDB` на GitHub runner и на машине,
  где редакция или путь Visual Studio отличаются от машины сборки LLVM.

### Корректные Windows-пути

- В `server/src/Paths.cpp` обратная косая черта заменяется при формировании
  внутренних идентификаторов так же, как прямая косая черта.
- В `server/src/utils/path/FileSystemPath.cpp` переменная `PATH` на Windows
  разбирается через `;`, а на POSIX — через `:`. Отсутствующая переменная `PATH`
  теперь обрабатывается безопасно.

### Запуск KLEE и сбор статистики

- На Windows используется поставляемый вместе с KLEE `klee-stats.py`, если в
  системе доступен Python.
- Python не является обязательной зависимостью portable-пакета. Если его нет,
  генерация тестов продолжается, а временная статистика KLEE записывается
  нулевой.
- Ошибка необязательного `klee-stats` больше не прерывает разбор `.ktest` и
  создание исходников тестов.

### Логи portable-программы

- UTBot сам создаёт каталог логов до открытия файла.
- Исправлено формирование пути к основному лог-файлу.
- На Windows `latest.log` создаётся как hard link, поэтому запуск не требует
  права на создание символических ссылок или включённого Developer Mode.
- Ошибка создания ссылки выводится как предупреждение и не останавливает
  генерацию.

## Изменения GitHub Actions

### Воспроизводимые зависимости

- Добавлен vcpkg manifest с закреплённым baseline
  `56bb2411609227288b70117ead2c47585ba07713`.
- Явно заданы `grpc[codegen]` и `protobuf`. Feature `codegen` нужен не только
  для инструментов генерации, но и для цели `gRPC::grpc++_reflection`, с которой
  линкуется UTBot.
- Добавлены отдельные Release-only triplet:
  - `x64-windows-static-release` — статические библиотеки и статический CRT для
    целевого `utbot.exe`;
  - `x64-windows-release` — host-инструменты `protoc` и `grpc_cpp_plugin`.
- Debug-варианты gRPC/Protobuf больше не собираются для Release-архива.

### Кэш и время сборки

- Загрузки vcpkg и бинарные пакеты хранятся раздельно.
- Вместо кэширования установленного дерева размером более 20 ГиБ сохраняются
  сжатые бинарные пакеты vcpkg.
- Завершённые пакеты сохраняются даже после ошибки или тайм-аута следующего
  порта.
- Кэш может переиспользовать ABI-совместимые пакеты после изменения manifest;
  несовместимые пакеты vcpkg автоматически перестраивает.
- Для gRPC оставлены повторные попытки и отдельный лимит времени 240 минут.
- Устаревшие запуски одной ветки отменяются. Push и Pull Request одной исходной
  ветки используют общий concurrency key и не занимают два runner одновременно.

### Проверки и артефакт

Windows workflow теперь выполняет следующую цепочку:

1. Собирает SQLite, KLEE и `utbot.exe` нативным Windows toolchain.
2. Проверяет импортируемые DLL и отсутствие зависимостей от MSYS/Cygwin.
3. Компилирует небольшой C-модуль в LLVM bitcode и запускает KLEE.
4. Проверяет полный интерфейс CLI через `utbot --help-all`.
5. Создаёт compilation/link database и запускает настоящую генерацию тестов.
6. Проверяет наличие файла тестов и не менее трёх случаев для трёх ветвей.
7. Собирает portable-каталог с UTBot, KLEE, Clang, LLVM tools, заголовками,
   runtime bitcode и необходимыми DLL.
8. Переносит каталог в другое место, очищает `UTBOT_ALL`, ограничивает `PATH` и
   повторно запускает KLEE, UTBot и генерацию тестов.
9. Загружает результат как GitHub Actions artifact.
